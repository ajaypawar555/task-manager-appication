# Task Manager API reference

Base URL for local development: `http://127.0.0.1:8000`

Interactive OpenAPI documentation is available at [`/docs`](http://127.0.0.1:8000/docs) while the server is running.

## Authentication

Every `/api/v1/tasks` endpoint checks the bearer token when `API_AUTH_ENABLED=true` (the default):

```http
Authorization: Bearer <API_ACCESS_TOKEN>
```

In Postman, choose **Authorization → Bearer Token** and paste the token value without the `Bearer` prefix. For isolated local testing, `API_AUTH_ENABLED=false` disables this check; restart Uvicorn after changing `.env`. Do not deploy or expose the API with authentication disabled. `GET /health` does not require a token.

The API requires a working Supabase URL and server-side secret key for task operations. The SQL migration must be applied to the same Supabase project. The publishable key does not have the table permissions used by this app.

## Task fields

| Field | Type | Rules |
|---|---|---|
| `id` | integer | Generated by PostgreSQL; returned by the API. |
| `title` | string | Required on create; 1–200 characters after trimming; cannot be blank. |
| `description` | string or `null` | Optional; maximum 5,000 characters. |
| `status` | string | `pending`, `in_progress`, or `completed`; defaults to `pending`. |
| `priority` | string | `low`, `medium`, or `high`; defaults to `medium`. |
| `due_date` | datetime or `null` | Optional ISO 8601 timestamp, such as `2026-10-20T17:00:00Z`. |
| `created_at` | datetime | Set by PostgreSQL when created. |
| `updated_at` | datetime | Set by PostgreSQL and refreshed on updates. |

## Endpoints

### Health check

```http
GET /health
```

No authentication required. Returns `200 OK` with `{"status":"ok"}`. This checks that the API process responds; it does not verify Supabase connectivity.

### Create a task

```http
POST /api/v1/tasks
Content-Type: application/json
```

Example body (only `title` is required):

```json
{
  "title": "Prepare project demo",
  "description": "Review the API and prepare a short demo.",
  "status": "pending",
  "priority": "high",
  "due_date": "2026-10-20T17:00:00Z"
}
```

Returns `201 Created` and the created task, including its generated `id` and timestamps.

### List tasks

```http
GET /api/v1/tasks
```

Optional query parameters:

| Parameter | Type | Default | Description |
|---|---|---:|---|
| `status` | string | none | Filter by `pending`, `in_progress`, or `completed`. |
| `priority` | string | none | Filter by `low`, `medium`, or `high`. |
| `search` | string | none | Case-insensitive substring search in the title; maximum 200 characters. |
| `limit` | integer | `20` | Page size, from 1 to 100. |
| `offset` | integer | `0` | Number of matching rows to skip; must be nonnegative. |

Example:

```http
GET /api/v1/tasks?status=pending&priority=high&search=demo&limit=10&offset=0
```

Returns `200 OK` and an array of tasks ordered newest first. No matches returns an empty array.

### Retrieve a task

```http
GET /api/v1/tasks/{task_id}
```

Example: `GET /api/v1/tasks/1`. Returns `200 OK` and the task, or `404 Not Found` with `{"detail":"Task not found"}` if the ID does not exist.

### Partially update a task

```http
PATCH /api/v1/tasks/{task_id}
Content-Type: application/json
```

Send one or more fields to change; omitted fields stay unchanged. For example:

```json
{
  "status": "completed",
  "priority": "medium"
}
```

Returns `200 OK` and the updated task. An empty body, invalid values, or `null` for `title`, `status`, or `priority` returns `422 Unprocessable Entity`. A missing task returns `404 Not Found`.

### Delete a task

```http
DELETE /api/v1/tasks/{task_id}
```

Returns `204 No Content` on success (no response body), or `404 Not Found` if the ID does not exist.

## Status codes

| Status | Meaning |
|---:|---|
| `200` | Request succeeded. |
| `201` | Task created. |
| `204` | Task deleted; response has no body. |
| `401` | Bearer token missing or invalid while authentication is enabled. |
| `404` | Route or task ID was not found. Check the response `detail` to distinguish them. |
| `422` | Request body or query parameter failed validation. |
| `503` | Task storage is unavailable or a database operation failed. Details are logged server-side, not returned. |

## Postman quick test

1. Start the app from the project folder: `uvicorn app.main:app --reload`.
2. Send `GET http://127.0.0.1:8000/health`; expect `200`.
3. Send `POST http://127.0.0.1:8000/api/v1/tasks` with the JSON example above. Set **Body → raw → JSON**. Add a bearer token if `API_AUTH_ENABLED=true`.
4. Copy the returned `id`, then send `GET http://127.0.0.1:8000/api/v1/tasks/{id}`.
5. Try listing, filtering, updating, and deleting with the endpoints above.

## Desktop UI

Start the API, then from a second terminal run `python ui.py` (or `.\.venv\Scripts\python.exe ui.py` in PowerShell). Enter the local base URL, and enter a bearer token only when `API_AUTH_ENABLED=true`. The desktop client supports task listing, filters, title search, create, update, and delete.

The browser UI is served from the same FastAPI app at `/`. It can be hosted with the API on Vercel; configure `SUPABASE_URL`, `SUPABASE_KEY`, `API_ACCESS_TOKEN`, and `API_AUTH_ENABLED=true` in Vercel's environment settings. See the Vercel deployment section in the README. The browser receives only the API token entered by its user, never the Supabase key.

## Troubleshooting

- `{"detail":"Not Found"}` usually means the path or HTTP method is wrong. Task collection routes use `/api/v1/tasks`.
- `{"detail":"Task not found"}` means the requested ID is not present in the configured Supabase project.
- `401` means authentication is enabled and the bearer token is missing or incorrect.
- `503` means the task database request failed. Confirm the SQL migration was run on the project named by `SUPABASE_URL`, and that `SUPABASE_KEY` is a server-side secret/service-role key.
- `GET /health` returning `200` confirms the server process is running, not that the database is reachable.

Never send `.env`, the Supabase secret key, or the API access token when asking for help.
